Request each review with ONE call to agmsg `send.sh`: `~/.agents/skills/agmsg/scripts/send.sh <team> <your agent name> <Review pane agent> 'review-code: <request text>'`. The recipient is the Review pane agent printed in the header, never a surface or workspace id, and a non-zero exit means the reviewer was NOT told, so report it instead of waiting for a verdict that can never appear. Read `reviewer_engine` from the review configuration; it must be the Review engine printed in the header, and you must never derive it from another role. Resolve the reviewer pane surface from the `review` entry of the prewarm.json in the status directory for the liveness check only. Never deliver a message by typing it into a pane yourself. The request must tell the reviewer to send you ONE message whose body starts with `review-verdict:` right after it writes the findings file. Do not poll that file: arm ONE single-shot safety timer — one `sleep $((30 * 60))`, a single sleep and never a loop — armed the way YOUR OWN engine allows, because the two engines wake differently: as a claude session, run it with the Bash tool and `run_in_background: true`; as a codex session there is no such tool and a bare background sleep never resumes the turn, so schedule a message to YOURSELF instead and wake over your bridge seat: `( sleep $((30 * 60)); ~/.agents/skills/agmsg/scripts/send.sh <team> <your agent name> <your agent name> 'review-timer: <round>' ) &`. Then stop and wait for that message. Re-read the findings file on every wake, whether the message or the timer woke you, because only the message can be lost; stop the timer as soon as you act on a verdict (claude `TaskStop`s the background task, codex kills the background subshell). If the timer fires with no VERDICT line, check the reviewer pane once for liveness, re-send the same round once, and re-arm the same timer; keep re-arming up to 3 times for that round. If the 3rd re-arm also fires with no verdict, record a skipped review and proceed — this is an unattended run, so there is nobody to ask.

If you stop before completing the work, do not stop silently. Write the reason to the round findings file with a last line of `VERDICT: needs_work`, tell the reviewer with one more `send.sh` call that is identical to the review request except that the body starts with `abort-reviewer: [abort]` followed by a one-line reason, write status `error` with the reason as message, then notify the parent with one final `send.sh` call addressed to the `parent` agent whose body starts with `dispatch-notify:`, and end the session. Writing the status file alone notifies no one.
