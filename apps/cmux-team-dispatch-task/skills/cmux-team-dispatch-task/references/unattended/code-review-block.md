Request each review with ONE call to agmsg `send.sh`: `~/.agents/skills/agmsg/scripts/send.sh <team> <your agent name> <Review pane agent> 'review-code: <request text>'`. The recipient is the Review pane agent printed in the header, never a surface or workspace id, and a non-zero exit means the reviewer was NOT told, so report it instead of waiting for a verdict that can never appear. Read `reviewer_engine` from the review configuration; it must be the Review engine printed in the header, and you must never derive it from another role. Resolve the reviewer pane surface from the `review` entry of the prewarm.json in the status directory for the liveness check only. Never deliver a message by typing it into a pane yourself. The request must tell the reviewer to send you ONE message whose body starts with `review-verdict:` right after it writes the findings file. Do not poll that file: arm ONE single-shot safety timer as a background sleep of 1800 seconds, one sleep and never a loop, then stop and wait for that message. Re-read the findings file on every wake, whether the message or the timer woke you, because only the message can be lost. If the timer fires with no VERDICT line, check the reviewer pane once for liveness, re-send the same round once and re-arm the timer, then record a skipped review and proceed if the re-armed timer also fires with no verdict.

If you stop before completing the work, do not stop silently. Write the reason to the round findings file with a last line of `VERDICT: needs_work`, tell the reviewer with one more `send.sh` call that is identical to the review request except that the body starts with `abort-reviewer: [abort]` followed by a one-line reason, write status `error` with the reason as message, then notify the parent with one final `send.sh` call addressed to the `parent` agent whose body starts with `dispatch-notify:`, and end the session. Writing the status file alone notifies no one.
