Phase A-R is assigned to the `design_review` pane. Use the Design review agent, runner, engine, model, and effort printed in the Phase A-R block; do not derive them from the design, execution, or exec-review role. After preparing the plan, request review from that configured pane. The request must require `design-round-N.md` in the status review directory and its last line must be `VERDICT: approve` or `VERDICT: needs_work`. The request must also tell the reviewer to send you ONE message whose body starts with `review-verdict:` right after it writes that file. Do not poll the file: stop and wait for that message, and re-read the file on every wake because only the message can be lost. A claude session arms ONE single-shot safety timer before it stops; a codex session has no safety net for this wait and must not pretend to arm one (see the code review block for what to do instead). If the timer fires with no verdict in the file, re-arm the same timer and wait again, up to 3 re-arms for that round; once the 3 re-arms are used up with still no verdict, skip the review for that round and proceed — this is an unattended run, so there is nobody to ask. On needs_work, apply valid findings and repeat for at most five rounds. If the fifth round still needs work, record unresolved findings and continue. Do not ask a human question.
