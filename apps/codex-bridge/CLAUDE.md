# codex-bridge

Claude Code の rules / CLAUDE.md を Codex 用 `AGENTS.md` にネスト生成する汎用プラグイン。

## 仕組み

- `.claude/rules/*.md` の frontmatter `codexTargets: [<dir>/, ...]` を正として、各 `<dir>/AGENTS.md` を生成。
- root `CLAUDE.md` → root `AGENTS.md`。
- `--global`: `~/.claude/CLAUDE.md` → `~/.codex/AGENTS.md`。
- 生成物は先頭に `GENERATED by codex-bridge` センチネルを持つ。センチネル無しの既存 `AGENTS.md` は手書き扱いで上書きしない。

## サイズ上限

有効な上限は `--max-bytes` > `~/.codex/config.toml` の `project_doc_max_bytes` > Codex 既定の 32768 の順に決まる。超過しても書き込みは行い、診断を出す（Codex 側は超過分を黙って切り捨てるため、警告を出さないと末尾が読まれていないことに気づけない）。

診断は超過の種類を区別する。ここを取り違えると効かない対処を提案してしまう。

- **連結超過** (`concatenation-over-limit`): 個々の rule は上限内だが結合で超えた。`codexTargets` をより深いディレクトリに割り当て直せば解決する。
- **単一 rule 超過** (`single-rule-over-limit`): 1 つの rule だけで上限を超えている。**`codexTargets` の付け替えでは解決しない**（同じ本文が別パスに移るだけ）。rule ファイル自体の分割か削減が必要。

実際の修正は `commands/codex-bridge.md` の手順に従って Claude が対話的に行う。分割位置と `codexTargets` の選定は「どのエージェントがどこで何を読むべきか」という編集判断なので、無人では適用しない。

## 開発

```bash
bun test              # src/generate.test.ts
pnpm --filter @tanaka-yui/codex-bridge check
```

ロジックは `src/generate.ts` の純粋関数（parse / render / group / decide / size）と、fs を触る収集・書き込み・main に分離されている。純粋関数を優先して TDD する。

## 関連プラグインとの境界

cmux 系プラグインとは責務が独立。本プラグインは「Claude 設定 → Codex 設定」の一方向変換のみを担い、cmux トポロジや実行オーケストレーションには関与しない。

## 言語ルール

- **ドキュメント・コメント**: 日本語
- **コード（変数名・関数名・コマンド）**: 英語
- **`SKILL.md` / `commands/*.md` / `references/*.md`**: **英語必須**。日本語訳は `references/*-ja.md` に置く。
  詳細はルート `CLAUDE.md` の「Language convention」を参照。検証は `pnpm check:doc-lang`。
- **例外**: `SKILL.md` frontmatter の `description` は日本語可（起動トリガー語を残すため）。
