# codex-bridge 設計

## 目的

プロジェクトごとに存在する Claude Code の rules（例: `.claude/rules/*.md`）と `CLAUDE.md` を、Codex が読める `AGENTS.md` に **ネスト生成** する汎用プラグイン。プロジェクトスコープとグローバルスコープの両方に対応する。

### 背景と制約

- Claude Code は `.claude/rules/*.md` を CLAUDE.md 参照 / subagent / skill 経由で **必要な時だけ条件ロード** する。
- Codex は `AGENTS.md` を **リポジトリ root → cwd までディレクトリツリーをマージして自動ロード** する。Claude のような条件ロード機構は無い。
- Codex の AGENTS.md には **サイズ上限** があり（`project_doc_max_bytes` 既定 32KB）、超過分は切り捨てられる。全 rule を 1 ファイルに詰めると壊れる。
- Codex は Claude の `@path` import のような **自動インクルードを追わない**。

→ ディレクトリごとに `AGENTS.md` を生成する「ネスト生成」が、Codex のツリーマージと Claude の条件ロードの双方に最も近い。

## スコープ

| 項目 | 内容 |
|------|------|
| 対象 | 複数プロジェクトで再利用できる汎用プラグイン（yui-cc-plugins に追加） |
| 方式 | `.claude/rules/*.md` を正として各ディレクトリの `AGENTS.md` を生成 |
| マッピング | 各 rule ファイルの frontmatter `codexTargets` で宣言 |
| トリガー | 手動スラッシュコマンドのみ（git hook / CI は今回スコープ外） |
| root 扱い | root `CLAUDE.md` → root `AGENTS.md` も生成 |
| グローバル | `~/.claude/CLAUDE.md` → `~/.codex/AGENTS.md`（Codex の日本語応答を実現） |

### 非スコープ（YAGNI）

- git pre-commit hook / CI `--check` モード（必要になってから追加）
- CLAUDE.md → AGENTS.md 変換時の Claude 固有記述フィルタ（v1 は verbatim）
- target ディレクトリの自動作成

## アーキテクチャ / コンポーネント

新規プラグイン **`codex-bridge`**（`apps/codex-bridge/`）。標準プラグインレイアウトに従う。

```
apps/codex-bridge/
├── .claude-plugin/plugin.json      # マニフェスト（version は marketplace.json と同期）
├── commands/codex-bridge.md        # /codex-bridge スラッシュコマンド
├── bin/generate                    # 生成本体の実行エントリ（Bun/TypeScript）
├── CLAUDE.md                       # プラグイン固有ガイド
├── package.json
└── src/
    ├── generate.ts                 # 生成ロジック
    └── generate.test.ts            # Bun test
```

**実装言語: Bun/TypeScript。** frontmatter（YAML 配列 `codexTargets`）のパースが bash では壊れやすく、cmux-team / cmux-remote と同じ Bun ランタイム規約に乗れるため。

### 生成モード（1 コマンドが引数で分岐）

| モード | 入力 | 出力 |
|--------|------|------|
| project rules（既定） | `.claude/rules/*.md` の frontmatter `codexTargets` | 各 `<target>/AGENTS.md` |
| project root（既定に含む） | リポジトリ root `CLAUDE.md` | root `AGENTS.md` |
| `--global` | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` |

## データフロー

```
.claude/rules/*.md ──parse frontmatter──▶ codexTargets でグループ化 ──▶ <target>/AGENTS.md
CLAUDE.md (root) ─────────────────────────────────────────────────▶ root AGENTS.md
~/.claude/CLAUDE.md ──(--global)───────────────────────────────────▶ ~/.codex/AGENTS.md
```

### 生成ファイルの構造

frontmatter を除去した rule 本文を、生成ヘッダー（センチネル）付きで結合する。

```markdown
<!-- GENERATED by codex-bridge. DO NOT EDIT.
     Source: .claude/rules/go-backend.md, .claude/rules/go-testing.md -->

# (concatenated rule bodies)
```

### rule frontmatter の例

```markdown
---
description: Go backend rules
codexTargets:
  - go/
---
# Go Backend Rules
...
```

複数 rule が同一 target を指す場合は 1 つの `AGENTS.md` に結合する。

## 安全性ルール

1. **上書き保護** — 出力先に既存 `AGENTS.md` があり、先頭に `GENERATED by codex-bridge` センチネルが **無い** 場合は、手書きファイルとみなして **上書きせず警告**（サマリに列挙）。センチネル付きなら再生成で上書きする。
2. **サイズガード** — 生成結果が `project_doc_max_bytes`（既定 32KB）を超えたら **警告**（切り捨てリスクを通知）。分割はユーザーが `codexTargets` をより深いディレクトリに割り当てて対応する。
3. **冪等性** — 同一入力なら再実行で差分ゼロ（frontmatter 順・target 順を安定ソート）。

## エラー / エッジ処理

| ケース | 挙動 |
|--------|------|
| rule に `codexTargets` が無い | スキップ + 警告（「未マッピング rule」としてサマリに列挙） |
| target ディレクトリが存在しない | スキップ + 警告（自動作成はしない） |
| 複数 rule が同一 target | ファイル名順で結合し 1 つの AGENTS.md に |
| `CLAUDE.md` / `~/.claude/CLAUDE.md` が無い | そのモードをスキップ + 通知 |

実行後に **サマリ** を出力する（生成した AGENTS.md 一覧 / スキップ / 警告）。

## スラッシュコマンド UX

| コマンド | 動作 |
|----------|------|
| `/codex-bridge` | プロジェクト生成（`.claude/rules/*` → ネスト AGENTS.md ＋ root `CLAUDE.md` → root `AGENTS.md`） |
| `/codex-bridge --global` | グローバル生成（`~/.claude/CLAUDE.md` → `~/.codex/AGENTS.md`）のみ |

コマンド `.md` は `bin/generate` を該当引数で呼び、サマリを表示するだけの薄いラッパにする。

## テスト（Bun test, `src/generate.test.ts`）

- フィクスチャ（frontmatter 付きサンプル rule 群）→ 正しい target にグループ化・結合されるか
- センチネル付与、および **手書きファイル上書き拒否** の挙動
- 32KB 超過時の警告
- `codexTargets` 欠如 rule のスキップ + 警告
- 冪等性（2 回実行で差分ゼロ）

## 成功基準（検証ループ）

1. `codex-bridge` プラグインで対象プロジェクトに対し `/codex-bridge` 実行 → `go/AGENTS.md` 等が生成され、Codex が該当ディレクトリで rule を読む。
2. `/codex-bridge --global` → `~/.codex/AGENTS.md` 生成 → Codex の応答が日本語になる。
3. `bun test` 全パス / `pnpm check` パス。

## バージョン同期

`apps/codex-bridge/.claude-plugin/plugin.json` の version を更新したら、ルートの `.claude-plugin/marketplace.json` にも対応エントリを追加・同期する。
